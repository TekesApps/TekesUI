GPU 单帧耗时在 60/120 轮次分别下降约 2.27% / 1.90%，属于小幅收益，不能把单次顺序采样当作统计显著结论。60 FPS 的 CPU 增加 1.89 个百分点，120 FPS 降低 0.87 个百分点，不声称 CPU 一致改善。120 FPS 的窗口 GPU 忙碌比例仍约 88%，继续默认 60 FPS。保留全部灯光、软阴影、窗景与列车内饰，没有降低分辨率或删减灯光。

每轮同一资产与可执行配置，夜景、R 默认相机、A 持续旋转、B 后台测试开关；内置屏 Fill 窗口 3024×1730，3D 目标 2960×1362，4× MSAA。采样时没有编译、测试或导出任务。CPU 为 proc_pid_rusage，GPU/FPS 为同 PID 的 Metal Performance Overview 安全表；每轮原始计数覆盖约 60 秒。CPU 采样和 Instruments 启停存在小幅时间偏移；R 后启动和导出间隔也可能造成小量时钟差异，未严格锁定城市状态起始帧。未隔离桌面其他进程或系统功耗/温度，不能从这一对样本推断 CPU 差异的因果。

GPU Begin to End 是计数窗口按帧数加权的均值，不是单帧 P95，也不是 FPS 的倒数。窗口 GPU 忙碌比例不是全设备利用率。进程物理 footprint 约 588–646 MiB（各轮详见 JSON），属于统一内存，不能当独立显存占用。

基线保持最终的铁路/站台资产、实例 ABI、GPU 时钟、预计算与排序，仅替换回原 fragment 阴影/衰减数学；不是拿加电车前的老街区对比。基线也运行暂未使用的 inverse 预计算，因此本表隔离的是 fragment 路径收益。旧 baseline60 / before60 使用中间场景，不纳入最终结果；e235-before60 因进程已退出而 attach 失败。最后一轮完成后采样进程退出，final-after120-after.jpg 是重新打开的默认尺寸窗口，不能作为该轮结束时尺寸证据；该轮采用开始截图及完整 60 秒 CPU/Metal 计数。

## 通用 GPU 改动

- 阴影代理的半径/淡出倒数与灯光 radius² 倒数在共享 compute 中预计算，避免每个片元重复除法。
- 接收点偏移移到灯循环外；半影范围外跳过平方根；完全遮挡后提前终止剩余代理查询，保持原 min/soft-shadow 语义。
- 阴影缓冲增加 1536 字节，实例记录 160 → 192 字节用于通用路线可见性/时间表；不逐帧上传人物、灯位或顶点。
- 透明实例在 GPU 中按 primitive 排序，每个 primitive 最多 64 个实例；组间仍使用已有相机排序，不是全局 OIT。
- RouteSchedule3D 组合路线运动与四肢摆动；Transit 组合停车、加减速、开门。透空边界修正为整节车厢一致淡出，不切开车体截面。

## 独立铁路配方与模型

`city_transit.py` 管地面双轨、接触网和岛式站台；`city_train.py` 管空心车体、驾驶室、车门、纵向座椅及乘客；`city_train_liveries.py` 管可替换涂装。`transit.rs` / `station.rs` 只生成不可变配方，运动在 Scene3D 的 wgpu 路径计算，不把城市需求塞进通用渲染器。

原创 E235 风格三节演示列车，银色车身、绿色竖向门区、四组双扇门，造型参考 [JR East E235](https://www.jreast.co.jp/train/local/e235.html) 与[官方车型介绍](https://www.jreast.co.jp/press/2014/20140701.pdf)。没有导入商业模型、照片或铁路标志；不是实际十一节运营编组或工程尺寸复刻。车内有背靠侧窗的纵向座椅、坐姿与站姿人物，夜间 LED 与内饰自发光；站台人数由附近已入住居民/工作人口估计，数量有上限。GPU 时间表先下后上，门、人物和车体共用周期。
