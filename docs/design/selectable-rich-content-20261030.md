# Selectable rich documents — Issue 25

This increments [#25](https://github.com/TekesApps/TekesUI/issues/25) beyond passive Markdown/CodeBlock/Diff views. Agent message, tool facts and host URL policy remain with consumers. The styled decorative label slice is independent; this document does not reopen it.

## One original text owner and layout

`composition::RichContent::new(identity, revision, RichDocument)` mounts one original readonly `TextFieldContent` in Content presentation. There are no block TextFields, field backgrounds, message bubbles, copied selection engine or extra native text owner. `RichDocument::from_markdown`, `from_code` and `from_diff` accept general SDK models and source text.

The original injected `TextSurfaceHost::shape_surface` shapes each block at its SDK role and actual width/type scale. The library combines those original lines into **one retained Paragraph**, translating line UTF16/byte ranges, carets, glyph cluster/index ranges, line tops and baselines into its flattened document domain. Font identities and actual advances remain the original shaper's. Each nonfinal block includes its LF; the redundant trailing empty line belongs to the next block. Paragraph spacing uses the existing `space-relaxed` token.

The original TextSurface consumes that Paragraph for drawing, direct selection/capture, keyboard movement and selection, clipboard text, native firstRect/characterIndex/selectedRange and AX text projection. Paint may filter retained lines to apply original diff semantic ink; it never shapes another layout. Complete content and offscreen line geometry remain available through the existing original `ContentTextLayout`; clipping only limits visible native geometry. At a shared line boundary, the native projection orders the original same-index coordinates with the same downstream affinity as Paragraph::caret_rect. Both original coordinates remain available for a preceding range end. This avoids a native firstRect start selecting an old line-end coordinate with no following endpoint; hard and soft line starts are checked against the original Paragraph. No new platform input or selftest infrastructure is introduced.

## Source, display and immutable UTF16 mapping

`RichDocument` retains exact source, flattened display text, immutable blocks and links. Public getters cannot change validated ranges. Markdown shares its bounded parser with `Markdown::parse`, preserving the old model projection: headings, paragraphs joined from source lines, bullet lines and fenced code, including incomplete fences. Headings use UiHeading, body and bullets UiBody, code/diff Code. Unsupported inline formatting, nested/escaped links and inline code formatting stay literal. Simple `[label](target)` renders the label and records its target as data. Code is literal; no syntax highlighting is claimed.

Selected/copy text is the **display** projection: heading/fence/link-target syntax is omitted, bullet `• ` prefixes and one LF between blocks are included, and CRLF/CR become LF. Code/diff paint display line numbers using the original caption typography and a library-measured gutter. The gutter shifts the same paragraph glyphs/carets and is decoration, with no text/AX owner. Code copies source body without fences or line numbers; diff copies displayed line bodies with LF, including both removed and added bodies, without synthesized +/- prefixes or line numbers. Diff kind supplies the existing `status-succeeded` / `status-failed` ink.

`display_to_source` and `source_to_display` take half-open UTF16 ranges. Endpoints must be whole grapheme boundaries; reversed, out-of-bounds or partial surrogate/combining/ZWJ endpoints reject with None. A nonempty range start maps toward the visible text on its right, its end toward the text on its left. A syntax-only source range collapses at the right-side display point rather than producing a reversed range. A synthesized separator maps to the preceding source endpoint (or its actual source LF where equivalent). A display-end caret maps to the last block's source end, which can precede a closing fence; a source-end caret maps to display end. These are explicit projection rules, not an identity offset promise.

## Versioned updates and callbacks

`version()` returns an opaque token bound to this original input instance, document identity and revision. `update(expected, next_revision, document)` rejects another identity, another same-name instance, stale expected token and nonincreasing revision before mutation. Ordinary selection does not invalidate the token. The original controlled TextInput update maps directed selection through the retained grapheme prefix/suffix; selection in replaced text collapses to the replacement end. A changed heading/code role with identical display text explicitly invalidates only derived layout, including the intrinsic measurement cache. Before the next layout old text geometry is unavailable. Another business document mounts a new RichContent; updates do not switch identity implicitly.

Readonly remains immutable to Commit/Preedit, AX value/replace and deletion. Updates do not focus, send, commit/cancel or touch another composer's marked text. Plain pointer gestures retain original drag selection. Cmd-click, Cmd-Enter at a link, and the original AX Link part enqueue a `RichLinkAction` with original document/revision, source/display range, target and Pointer/Keyboard/Accessibility provenance. `drain_link_actions` transfers these once to the host. The SDK does not open URLs, access files or interpret schemes. Each accepted update retires previous link part keys, so an old native AX element cannot invoke a new target at the same ordinal. Link parts are owned semantic descendants, not additional text owners or form submissions; AX link activation preserves existing focus.

## Existing reading composition and independent consumer

`block_geometry()` exposes original Paragraph block bounds in host coordinates. Rich Content can be a stable item in the existing `ScrollContent` reading transactions and #42 checkpoints; the consumer uses semantic item IDs and versions, never estimates a scroll delta. Checkpoints retain their existing item-local logical-point semantics; this does not claim semantic character anchoring inside a reflowed block or virtualized large documents.

`examples/composition-consumer/src/rich_content.rs` independently mounts one continuous Markdown message, a code source and a multi-change diff, plus a separate original composer. The fixed reader explicitly opens at its heading; follow-latest remains the existing separate intent. It demonstrates library-controlled append (retaining the current declared reading item set) and mixed-history prepend through `update_scroll_reading_document`. Its tests cover original layout/native projection, cross-block Unicode copy and drag selection, expected-version rejection, same-text role reflow, theme/width/scale changes, link provenance, readonly protection, composer marked isolation and reading checkpoints.

The standalone `rich_content` native example reuses original CoreText, key, pointer, AX and existing selftest adapters. Its ordered acceptance script requests actual AppKit/AX Unicode selection, native substring/firstRect queries, copy through the host clipboard, readonly rejection, AX link callback, synthetic composer marked isolation under background append/narrow/dark reflow, code/diff copies and normal close. These are prepared assertions until execution receipts and pixels are reviewed. Synthetic preedit, physical IME, VoiceOver, GPU pixels and performance remain distinct evidence. No physical IME or VoiceOver pass is inferred from software input. F5 projection editing and virtual documents remain outside this increment.
