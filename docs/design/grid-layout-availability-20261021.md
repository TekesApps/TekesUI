# GridView：零面积不发布可绘制／命中的子项

根因属于公共布局视图的可用性契约。Grid 模型提供自然内容布局，即使测量约束高度为0，也可生成有高度的行；这是测量能力。GridView 直接把这些结果包装为可见子项，却没有判断自己的布局是否仍可用。父布局高度为0、visible为空时，消费者仍能得到可绘制和可命中的子矩形。

共享修复只在 `layout_view.rs::GridView::render`，复用已有 `has_area` 检查。没有新 token、协议、公共参数或状态层。所有 GridView 消费者统一受益，Gallery 原有接法直接得到修复；没有页面局部隐藏或样式补丁。

适用范围及例外：

- 非零布局仍保留原来的自然行溢出，由真实祖先视口裁剪，不能强行改成按名义高度裁切。
- 纯 `Grid::layout` 的零高度测量能力不变。
- Stack 原有零面积几何已不发布可见子目标，已回归核对，不为统一名称再加一层封装。
- GridView 只提供几何，不拥有子控件模型、AX树或业务状态；消费者仍按当前发布槽位路由事件，并复用子控件已有捕获取消能力。此修复不冒充新的自动卸载／焦点／可访问性协议。

修复前，公共 API 回归真实失败；96个真实GPU场景中48个零高度场景仍绘出了子按钮。当前3项公共回归转绿，419项controls测试及严格Clippy通过。实际Gallery从正常到零面积再恢复的接入测试通过，168项独立消费者测试及双方严格Clippy通过。

独立小宿主使用真实GridView、Button、CoreText和Metal。当前96场景覆盖4主题、3品牌、两宽度、@1/@2；48个零面积结果与空场景参考相同，48个正常结果与修复前逐像素相同。当前每次重放144帧；修复前96帧单列保存，不混报为同一次运行。

15份真实重跑token观测共5928有界场景。GridView的96项捕获明确为几何层零动态lookup；真正的主题化子Button绘制在捕获范围外，不把子控件的依赖归入Grid，也不把空集合说成完整依赖闭包。complete=false。44项治理、8项组合及3项生成公共绑定检查通过。

外接屏U2790B @2实际激活的小宿主保留同一组Button对象：正常点击后动作计数1，父布局置零后原位置点击仍为1，恢复后点击为2。鼠标只按GridView发布的槽位命中，没有另加隐藏开关挡住事件来制造通过。宿主仅有功能验收所需数据、原生事件适配与日志；AX/VoiceOver不在本宿主范围。窗口已关闭，产物按无人使用检查后清理。
