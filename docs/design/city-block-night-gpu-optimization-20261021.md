# 夜景 GPU 阴影筛选优化（2026-10-21）

继续使用当前 Gallery worktree 和既有 target，保留其他未提交改动。建筑几何与贴图保持原有资源；新增竣工窗景激活元数据（GLB 净增加 24 字节），最终 SHA256 另行记录。保留灯光、阴影、窗帘、窗内人物动作、车辆/行人、水面、树木和施工效果。按本轮追加需求，将原来各窗户独立的动态状态改成共享视觉样式，具体随机时序允许重复。

## 实现

自动旋转现在与自主街区动画共用 60 Hz 呈现预算；手动拖动和显式重绘仍可使用原生刷新节奏。模拟时钟和相机旋转仍按实际 dt 连续推进，不通过减少运动距离省开销。

原片元着色器在每盏有效局部灯光下，遍历全部阴影代理。现在先执行 GPU 附件动画，再执行 GPU compute，为每盏灯生成按原顺序排列的阴影候选索引；片元阶段只扫描候选。候选列表每帧由 GPU 重建，没有 CPU 回读，也没有每帧 CPU 上传列表。

剔除采用保守几何界限：灯光有效球与阴影椭球包围盒不相交，则无法遮挡球内接收点到灯光的线段。界限包含原公式的 1.12 倍软阴影范围、0.035 接收面法线偏移及浮点余量。所有保留下来的代理使用原始椭球相交/柔化公式，原有最多 64 灯 / 96 代理的能力上限不变。额外固定 GPU 存储为 24832 字节（24.25 KiB），没有新增纹理、渲染目标或顶点副本。

施工切入夜晚时明确保存已建施工时钟，楼体、立面、脚手架、防尘幕布、围挡、吊车及工地灯附件共享该值；天亮扣除夜间停工时间，从保存进度继续。重复选择 Night 不重置进度；已拆除的临时结构不重新出现。

竣工立面通过通用材质 `tekes_interior_activation` 读取施工时钟，在脚手架及吊车完成退场后用 2 秒渐变启用 50% 入住率窗景。施工中保持空置/不亮室内灯，夜间施工时钟冻结也不会提前入住。新增 GPU 图像测试固定立面可见性、普通楼窗景时间及光照，仅改变施工时钟，确认完工后出现真实窗内亮灯，且仍只求 32 组共享状态、不重新上传几何或实例。

## 共享窗景

新增独立 InteriorGpu 模块和 32 组固定视觉样式的 GPU 状态库。人物走动、坐下/阅读、窗帘闭合度、灯光活动每帧由一个 32 线程 workgroup 计算一次；不同建筑/朝向/窗格以稳定种子映射到样式。暂停/相机独立变化时复用状态，只有时间、夜间原点或灯光模式变化才更新。光照有两种色调、帘布有四种颜色，入住率仍按窗格单独稳定分配（50% 仍为每 4×4 组中固定 8 格）；空置房间不因此亮灯。

这是共享模拟状态，不是逐窗模拟；各窗户仍需完成自身像素绘制，矢量剪影和布帘边缘保留原有清晰度，没有增加低分辨率动画帧贴图。固定状态库仅 1536 字节，GPU 自产自用，不逐帧上传人物/帘布/灯光状态。连同阴影列表，新增固定存储共 25.75 KiB。

## 原生性能测量方法

Apple M4 / 10 逻辑核 / 32 GiB 统一内存。原生 release App，1512×833 pt 内容窗口、2× backing，3D 目标 2960×1362 px、4× MSAA。明确选择 Night，复位初始场景，Animation 菜单打开保持 common-runloop 的可见持续渲染。两组为固定视角街区动画、街区动画加自动旋转。

优化前后的 GPU 都在本轮重新录制，每组 60 秒，使用仅 Metal Performance Overview 的目标 PID / layer 指标；不启用大体积 Resource Events。CPU 与 GPU 独立采样，CPU 为每秒累计 user+system 时间差，100% 表示一个逻辑核。GPU Usage 为窗口 GPU 活跃时间占帧间隔的比例，不是整机 GPU 使用率。后台桌面程序未关闭，结果是当前桌面环境下的数据。

记录、逐秒采样、构建及资源 SHA256 见同名 JSON；验收日志、截图和基线可执行文件保留在任务证据目录，原始 trace 导出必要表后清理。

缩放预算已按实际模型完成离线投影测算，见 `city-block-screen-detail-20261021.md/json`。其阈值尚未接入运行时物体 LOD / indirect culling，不能把这部分候选设计计入本次 GPU 优化收益。

每帧 GPU 时间分别降低约 39.5% / 49.4%。GPU 比例同时受帧率预算、相机遮挡和桌面负载影响，不能将其等同整机 GPU 或把所有收益归给共享窗景。最终旋转与固定动画都约 60 FPS。

每组录制请求为 60 秒，GPU Overview 的滚动计数器覆盖：基线 59.8795 / 60.2257 秒，最终 60.9993 / 59.4645 秒。汇总保留所有已报告计数器窗口，CPU 则为独立完整 60 秒采样。原生起止截图均验证最终各组为 3024×1730；先前发生尺寸变化的旋转组及过渡构建全部排除。

本轮未重新测旧版 CPU，不能把先前报告的另一构建/桌面环境的 CPU 数字当作本轮因果对照。本轮 CPU 当前值如表；没有宣称 CPU 获得改善。进程 footprint 包含统一内存资源，不能与 Metal 分配相加；本轮未录制高体积 Metal Resource Events，未声称新的独立显存峰值。
