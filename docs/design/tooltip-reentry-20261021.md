# Tooltip：Escape 后的独立新进入恢复

## 根因与共享修复

此前原生检查发现：Escape 关闭后，如果键盘焦点保留，指针离开再进入仍无法显示；反向的新焦点进入也被保留的 hover 阻止。旧实现只有在两个旧显示来源都退出后才解除共同抑制。原生记录证明了旧行为，但没有证明它符合新的用户输入意图，不能仅因源码如此就作为体验豁免。

根因属于基础交互原语的恢复契约。JSON 唯一真源 `design/source/interaction-contracts.json` 新增 Tooltip 契约：活动状态下 hover 或 focus 的 false→true 是独立的新显示请求；不要求另一个旧来源退出。重复 true、区域内移动、重绘，以及只退出一个来源，不得重开。失活调用继续忽略，旧几何立即失效；受控 true 的抑制仍由调用者 false→true 重置，新用户来源与其独立。

`crates/tekes-ui-controls/src/feedback_view.rs` 只复用现有 hovered/focused/controlled_visible/dismissed_until_leave 判断可观察的进入边缘，没有新增字段、状态协议、原语、token、计时器或抽象层。JSON 投影已重新生成。已逐项比较旧新 proposal：所有已有颜色、排版、布局、动效和品牌值不变。

适用于全部公共 TooltipView 消费者，包括 Gallery FeedbackViews 转发方法和外部消费者。例外是没有新进入的既有来源继续受 Escape 抑制；非活动窗口的“新进入”不算用户请求；任意模型 true 重绘也不等于调用者重新显示。变更是可观察的恢复行为调整，公共签名及结构保持不变，不宣称完全没有行为变化。

## 分层验证

目录：`design/reviews/tooltip-reentry-20261021/`。

- 公共 API：新回归的两个恢复场景在旧代码真实失败；失活隔离原先通过。补查受控隐藏／显示与旧输入来源混合时，又复现一项失败；最终修复后四项检查、426 项 controls 回归及严格 Clippy 通过。旧失败和构建环境错误日志保留。
- 真实 Gallery 转发方法：四主题、三品牌、两种新来源，检验重复通知、退出、重入和失活。按当前 `gallery` 检查日志确认结果，不以页面存在代替验证。
- 外部公共 Tooltip 渲染及 token 观察扩展为 20 个实际生命周期场景，包含新的进入、重复输入和保留另一来源的退出；关闭零读取继续显式断言。所有受影响的现有 token 证据在最终源码上重跑。
- CoreText／Metal：480 个场景、960 帧，四主题、三品牌、两宽度、两倍率、普通／1.5 倍文字、hover／focus 两种新来源及受控／非受控，并补受控 hide／show 与旧来源的混合场景。重复输入和单方退出保持关闭，新进入显示；像素与同条件普通显示 Tooltip 的独立实例完全一致。它证明显示恢复，不代表 ClientKit 视觉一致或 Gold7 整体通过。
- 最终原生通过 38 个真实活动检查点（其中37个为输入／受控恢复路径，1个为失活前准备）和 1 个真实失活检查点，U2790B@2；StaticText 节点随可见性增删，失活后立即清除几何和焦点，显式迟到调用被拒绝。记录保留原始原生键盘／坐标指针事件；不把 AX Press 算作指针、不把迟到调用注入算作物理输入。没有把旧 Tooltip 宿主或此前冻结包作为新共享源码的原生验收。

首轮 GPU 夹具把 4×3×2×2×2×2×2 的计数误写成 768，实际是 384；最后计数断言失败，场景本身已运行。已保留该日志和图，修正夹具计数后重新执行带源码稳定性检查的 GPU 验证。没有把夹具错误归为生产缺陷。
