# 结果状态与测量进度：独立消费者

## 实施判断

根因属于真实消费者接入缺口，而不是现有共享绘制实现缺失。现有 StatusBadge 的 Info 可以承载明确的“尚未验证”和“已取消”标签；现有 Running／Failed／Succeeded 表达其他结果。公共 enum 不承担调用者全部业务状态。本轮保留这个边界，不增加状态 token 或共享协议。

共享位置仍是 `extended::{Progress,StatusBadge}`、`feedback_view::{ProgressView,StatusBadgeView,SkeletonView}`、现有 ContentHost 与 JSON palette。本轮在独立、不可发布的 composition-consumer 工作区增加 `feedback_status` 示例，调用上述公共 API；没有修改共享控件源文件。

适用于实际需要同时呈现测量进度与结果状态的消费者。例外是调用者无法提供可测分母时只能呈现“进度未知”，不可伪造百分比；成功不能由进度达到 100% 自动推导。Info 的相同颜色不是相同结果，标签和语义值必须明确区分未验证、取消和普通信息。

## 实际接入

示例保留同一 ContentHost 与同一组视图实例，调用者通过 `Scenario::set(outcome, value)` 发布两项独立信息。六种结果：就绪、处理中、失败、已验证成功、尚未验证、已取消。进度是有效的 `[0,1]` 或未知；非有限／越界更新整体拒绝，不先改变结果。这个 setter 是示例的应用入口，不是新增的 Kit 协议。

- “尚未验证＋100%”仍是 Info、明确未验证文本和对应语义，不变成成功。
- 失败／取消可保留 45% 实际进度，进度条不改用成功／失败色。
- 未知进度明确显示文字，复用既有 indeterminate 片段；加载占位复用 Skeleton。
- 标签按文字服务测量，使用共享间距；StatusBadge 标签在自己的实体色背景内居中并受祖先裁剪。
- 整组为被动 Group，结果和进度同时写入语义 value；失败独立标 invalid。没有虚构 Progress 原生 role、AX 平台桥或 VoiceOver 结果。

## 分层验证与边界

证据目录：`design/reviews/feedback-outcome-consumer-20261021/`。

公共 API 的上一轮 4 项控件契约检查仍保持原有范围；本轮消费层两项检查包括 864 个主题、品牌、宽度、字号、结果和测量组合，以及无效发布原子性、被动事件不激活。独立工作区严格 Clippy 通过。全部消费者回归与实际 token 重跑见本轮机器记录。

CoreText／Metal 小渲染宿主直接使用该消费者，运行 576 帧：六结果、四主题、三品牌、两宽度、@1／@2、普通／1.5 倍字号。实际文字成形、状态语义和非空渲染均断言；保留默认品牌普通宽度／字号及窄宽／大字的 48 张图片。没有历史前图，因为这是新增接入场景，没有替换旧生产行为。这些图不是 ClientKit 的匹配参考，不将自生成画面当作 Gold7 验收。

本轮追加完成 U2790B@2 外接屏上 48 个真实活动窗口组合及原生 AX 值检查：四主题、六结果、600pt 普通字号／260pt 1.5 倍字号；保留 48 张实际窗口截图和 AX 记录。宿主只映射原有 Group 语义，没有虚构 Progress role。见 `native-acceptance.json`、`native-source-manifest.json` 和 `native-cleanup.json`。小宿主已关闭，约20MB应用副本与自身构建包已清理。

仍须完成适用 VoiceOver 听读和同条件 ClientKit／Gold7 对照。不能把自动文本语义断言当作人耳听读、不能把离屏 Metal 当作原生窗口输入验收。StatusBadge 的未验证／取消、Progress 的宿主结果组合已拥有真实消费者和自动绘制证据，整体体验保持未验。

受 `lib.rs` 新模块导出及示例测试追加影响的既有 token 记录逐份重跑；未受影响的记录需逐一核对全部输入哈希后复用。历史记录、冻结包和图片不覆盖。审计中的“公共组合协议缺失”不会因为增加示例 Component 就自动改为实现。

不测性能，不提交、推送、合入、打 tag 或关闭 Issue。测试与小宿主构建完成后按所有权清理可重建输出，保留源码、锁文件、快照、图片、日志与共享依赖。
