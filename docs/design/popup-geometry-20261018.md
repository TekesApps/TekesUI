## 根因与共享修复

根因属于公共组件契约与组合几何：MenuView 使用 `anchor.min_y()+42` 和 `viewport.max_y()-160`，无法表达真实输入框高度；Gallery 的 CommandPalette 又以固定高度布置触发器和查询框。过滤到零候选时，公共适配器仍绘制最小菜单表面，遮挡空结果反馈。

- `composite.rs` 的 MenuView 复用已有 `feedback_view::place_overlay`，按锚点底边、既有 `space-micro`、实测菜单高度及调用方可用区域决定向下或向上展开，并以现有滚动容器容纳受限内容。Tooltip／Popover 原有放置行为不变。
- 公开 `MenuView::measure` 与真实绘制共用行测量、焦点留白和既有最小表面高度。调用方现在能在绘制前预留空间，无需绘制探针；未另建布局协议。
- `FilteredMenuView` 零候选复用 cancel，返回 None，不绘制或拦截幽灵菜单；ComboBox／CommandPalette 的查询与 open 保持，空结果文案继续由宿主提供。普通 Menu／Select 的空模型行为保留。
- Gallery 两个选择场景接入原有文字测量及公开 MenuView 测量；CommandPalette Playground 触发器、查询框和反馈依次使用真实 frame，不以局部坐标补丁修饰截图。

适用范围是现有 Menu、Select、ComboBox、CommandPalette 的所有 MenuView 消费者。合理例外：当上下任一侧都放不下一整行时，继续使用既有视口内有界覆盖回退，避免生成不可操作的细条；这不是 portal 或新窗口能力。调用方的 visible_bounds 是放置视口，祖先 clip 仍负责绘制与命中裁剪，不将二者混同。极窄父容器、宿主边界选择及完整浮层组合仍须按消费者验收。
