# AppHost sidebar presentation and disabled swap — 2026-10-21

This update supersedes the swap control in `lazy-leading-swap-20261021.md`. The center/trailing swap toolbar contribution and R shortcut are removed. Each fixed module continues to own its content and toolbar; layout visibility remains outside nav.json.

Leading is dormant at startup. Its first visible animation sample mounts the existing module process; later hide/show retains that same worker and state. The two Host-owned visibility contributions remain fixed to the physical leading/trailing slots.

Host owns layout presentation through independent `StateTransition` channels. The duration and easing come from the existing Design System `disclosure_reveal` role (currently 300ms/standard). Reversing a side samples its current value before retargeting; the other side is unchanged. Presentation is snapped to device pixels, and the same panel geometry drives content viewport, toolbar allocation, texture clipping and input coordinates. Existing latest-viewport checks continue rejecting stale-frame content input. New Panel/splitter pointer interactions are temporarily gated during the layout transition; the fixed visibility controls remain interactive for reversal. Closing cancels prior pointer/toolbar arms immediately, retains paint until width reaches zero, then removes that region from drawing. Splitter tracking at rest remains direct, without interpolating pointer movement.

The host window display link schedules only active transitions. Window/application focus loss pauses presentation and cancels input; focus return resumes without consuming inactive time. System Reduce Motion resolves to the semantic endpoint immediately and does not replay old movement. Completion stops the animation clock requests; the module renderer still responds independently to genuine state/geometry updates.

Toolbar default typography, icon artwork, hover dimensions and measurement belong to shared TekesUI. This update preserves the current shared defaults. The human request was handed off for a separate shared calibration: align all toolbar element centers with native traffic lights; use capital-letter visible height and traffic-light diameter as the default artwork reference; design regular icons to one nominal artwork height, retain intentionally smaller symbols centered in a uniform button/hover box, and avoid per-icon runtime auto scaling. Do not claim that calibration is present in this App until it is integrated and checked.

Evidence: `design/reviews/sidebar-motion-20261021`. Unit coverage checks interrupt/reverse continuity, inactive clock exclusion, Reduce Motion endpoints, settled no-frame state, opposite-column fixed geometry, dormant module startup and content/input offsets. Native screenshots/click traces, shared source identity and signed executable are recorded separately. Screenshots of endpoints are not a frame-pacing benchmark; VoiceOver, physical display perception and performance remain outside this update.
