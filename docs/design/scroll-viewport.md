# ScrollArea 的 viewport 与惰性内容

正式需求以 `design/behavior/scroll-viewport.json` 为唯一真源，由 `design/integration.json` 引用。本文解释边界和实施顺序；容器与滚动几何快照及 Gallery 的真实裁切消费已接入，变化通知、惰性内容生命周期和超长文本虚拟化仍未完成。

## 目的

让很长的内容不会拖慢一个大小固定的容器。容器只创建、测量、排版和绘制当前所需内容，并保留少量有预算的预备区域。全文数据和索引可以独立存在；离屏不等于删除业务数据。

仅给整个场景加裁剪，仍可能已经创建和排版全部内容，不能称为 lazy display。只减少 GPU 提交，也不能解决首次打开或缩放容器时的整篇排版开销。

## 三层职责

| 层 | 职责 |
|---|---|
| ScrollArea | 容器裁剪、滚动位置、回弹、两轴策略、坐标转换、viewport 变化快照 |
| 惰性内容适配器 | 用索引定位范围，估算和测量尺寸，按稳定 key 创建、复用、回收，维护预算和阅读锚点 |
| 内容模型 | 全文或数据、选择、编辑历史、加载状态、无障碍语义；独立于离屏实例的生命周期 |

这三层共用基础能力；长文字、图标网格和变高列表不应分别发明一套滚动坐标和通知系统。

## 必须先定义的数据

- **布局 viewport**：容器中真实的可用裁剪矩形。区分边框、固定 inset、文档 padding 和滚动条占位，不能重复扣除。
- **实际可见范围**：将 viewport 变换到文档坐标，再与文档及祖先裁剪范围求交。正常 offset 与回弹 overscroll 分开；回弹空白不对应额外条目。
- **内容 extent**：总范围及其精度状态，允许暂时使用估算高度；不能为了知道高度先创建全部条目。
- **实现范围与预取范围**：分别服务组件实例和数据加载，有界、可取消；预取不能阻塞当前画面。
- **版本与锚点**：内容和布局的 revision、变化原因、稳定条目 key/文本位置及其在 viewport 中的偏移。

长文档需要全局高精度位置和 viewport 相对渲染坐标，避免大数值下的 f32 精度损失。当前 ScrollView 使用 f32，不能据此声称已支持任意长度文档。

## 变化如何传递

滚动、回弹、容器尺寸、倍率、字体、内容增删和测量修正都需要明确通知。同一显示周期内合并成一致快照，避免消费者看到新尺寸和旧 offset 的混合状态。

位置变化驱动画面移动；只有所需条目范围变化才触发创建或回收。不能每移动一个像素就重建全部组件。异步结果携带版本，旧宽度或旧内容的结果不能覆盖当前布局。

变高条目测量后，总高度可能变化。通过阅读锚点补偿位置，保持当前读到的内容稳定；上方插入或删除也遵守同样原则。原先贴底的容器按贴底策略处理，不能突然离开末尾。

## 文字需要单独落实的部分

当前可见行绘制已有二分定位与少量行级预备范围。当前文档也会复用 CoreText 的准备数据。这些能减少绘制和重复准备工作，但首次打开、改文和换宽仍会形成完整段落排版；选区及部分文字几何查询也仍可能遍历整篇行数据。

完整惰性文字显示还需要段落/块索引、按需排版和失效范围。复制全文、跨块选择、搜索跳转、撤销及 IME 必须通过模型保持正确。宽度变化时保留阅读/光标锚点，按预算推进新的排版；不能在主线程同步排完整篇超长文档。当前非 Send 的 CoreText/字体状态也不能直接丢到后台线程共享使用。

## 实施和验收顺序

1. 统一 viewport 快照、坐标转换、变化原因和合并通知，同时保留当前外观与交互。
2. 加入通用范围查询与惰性内容生命周期，先验证等高内容，再验证估算变高内容及锚点修正。
3. 将长文字的整篇布局拆成可索引、可失效、受预算约束的排版块。
4. 使用相同容器对比短、中、极长内容：首次显示、随机跳转、持续滚动、resize、CPU、内存、实际保留实例/排版块数和实际呈现间隔。

验收必须证明可见工作量随 viewport 与预算变化，而非随总条目数线性增长。120Hz 的目标仍使用 scroll behavior JSON 中的频率，检查整帧及实际呈现；当前尚未通过的掉帧和回弹问题继续保留，不能用完成这份契约代替性能通过。

## 滚动条显示与内容间距

`ScrollArea::set_scrollbar_visibility(horizontal, vertical)` 分别控制两轴指示条，默认均为 true（有溢出时显示）。它与 `set_scroll_policy` 的滚动许可独立：false 不改变 extent、offset、滚轮、触控板或程序滚动，只隐藏绘制并移除滚动条命中区；隐藏正在拖动的轴会释放捕获。Gallery 的导航侧栏明确设置为 false/false，仍可滚动。

`design/source/layout.json` 的 `scroll_area` 是展示间距的唯一来源，经设计导出器生成 Rust 常量：内容 padding 12pt，单行输入垂直 padding 8pt，滚动条宽 4pt、边缘 inset 2pt，侧栏左右 padding 16pt。文本区域的轨道位于外侧 padding 内，内容与轨道保持分离；多行的上下 padding 相等。单行保留独立的垂直值以容纳文字与光标。外置滚动条的页面 viewport 保留既有外围 gutter，不重复扣减内容宽度。隐藏指示条不触发内容宽度跳变。

## Gallery 宿主集成

Gallery 页面 viewport 通过同一个 `ScrollGeometry` 快照完成 viewport/document 坐标转换、可见矩形计算和祖先裁切；文字表面的绘制、光标、选择、滚动条与指针命中共用该可见范围。Workbench 预览在 Gallery 页面 viewport 上再提供一层裁切，输入框按当前 `TextEngine` 的实际段落高度分配行高，输入框下方内容跟随实际高度排布。ComboBox / CommandPalette 的候选浮层允许越过输入框边界，但仍被预览和窗口 viewport 限制。点击不可见的裁切部分不会获取文字焦点。

ScrollArea Story 页面直接将 ScrollArea 放入预览剩余区域，Gallery 外层 viewport 没有额外文档滚动；TextEditor 的多行编辑区也使用其容器剩余高度。上述宿主集成解决裁切与布局几何一致性，不表示长文档已做分块虚拟化，也不代表独立的 120Hz、掉帧或 CPU 验收已通过。
