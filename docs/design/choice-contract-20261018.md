基于 `bc3de79` 加全部 WIP，沿 #3／#8／#12／#14 处理公共交互与真实接入，不关闭 Issue。刷新 GitHub 仍为 14 个开放 Issue、0 个全状态 PR，原 Issue 更新时间未变。

## 根因、共享修复与例外

| 根因 | 修复位置 | 适用范围 |
|---|---|---|
| 指针释放使用上一次绘制的候选映射，没有核对当前禁用、关闭、查询、候选数据 | `FilteredMenuView` 保留已经展示的映射和标签；ComboBoxView／CommandPaletteView 在 hover/release 核对当前模型，失配复用 cancel；render 更新候选时撤销旧捕获 | 两个 View 的所有消费者；直接使用 FilteredMenuView 的调用方也获得重绘换内容时的取消保护。直接适配器没有外部模型参数，绘制之间的模型核对由其调用方负责 |
| CommandPalette 触发器读取旧禁用状态；公开 open 在禁用时仍清空查询并打开 | 原 CommandPaletteView 同步触发器可用性，复用 cancel；原模型 `open` 尊重 disabled | 指针、键盘、公开模型及 View open。未新增可用性协议或包装层 |
| 关闭弹层的状态变化被 Gallery 误记成执行第 0 项 | `ExtendedStory::key` 两个选择分支只对 Enter 确认记录选择 | ComboBox／CommandPalette。Escape 关闭仍报告键盘状态变化，不能冒充候选激活 |
| Select 捕获是否需要新增入口 | 公开回归证明现有 `set_disabled` 会取消旧捕获；本轮不改其实现 | 固定选项 Select 继续复用原 Menu；可编辑查询与 IME 属于 ComboBox，是合理差异 |

候选仍使用已有的索引与字符串身份契约。缓存标签用于确认当前对象与实际展示内容一致，不新增 item key 协议；完全相同的字符串与索引无法识别调用方所谓“新对象”，不宣称具有新的稳定身份保证。当前过滤结果与展示内容相同的查询变化不要求取消；内容或映射变化则拒绝旧释放，重新绘制后的新点击仍正常选择。
