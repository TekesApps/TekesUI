# GPU 灯光筛选：固定 60 FPS 对照（2026-10-21）

同帧率实测结果：GPU 每帧耗时降低，CPU 没有节省，反而升高。此前“CPU 升高主要由于帧数增加”的解释并不充分。这里只记录这一轮前台对照观察；尚未定位 CPU 增量来自命令编码、同步、驱动还是其他调度开销，也未做统计显著性检验。

## 有效测量条件

内置 Retina 屏，窗口 3024×1730，3D 目标 2960×1362，4×MSAA；夜景、街区动画、模型持续旋转；H 限制 60 FPS，窗口保持前台、不遮挡。每版采满 60 秒，CPU 每秒采样并同时录制轻量 Metal Performance Overview。先优化版、后基线版。两组起止截图尺寸均相同。

使用标准复位视角 R，两版完全相同。此前原近景 R+四次放大在 60 FPS 上限下基线实际只有 56.56 FPS，因此不能作为严格同帧率对照。这里没有修改灯光、纹理、模型、MSAA 或 LOD 阈值，但标准视角与原近景的可见细节/像素覆盖不同，不把本表称为近景固定60结果。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 原生实际 FPS | 60.02 | 60.00 |
| CPU 平均 | 16.24% | 21.82% |
| CPU 单秒 P95 | 18.20% | 24.89% |
| GPU begin-to-end 每帧平均 | 9.67 ms | 7.14 ms |
| GPU active time 每帧平均 | 9.37 ms | 6.87 ms |
| 窗口 GPU 活跃比例 | 56.26% | 41.24% |
| 进程 footprint 末值 | 518.14 MiB | 524.66 MiB |

CPU 上升 5.58 个百分点（相对 +34.4%），GPU begin-to-end 每帧平均减少 26.2%。窗口 GPU 活跃比例约从 56.26% 降到 41.24%，下降 15.02 个百分点。CPU 平均分别约等于每呈现帧 2.706 / 3.637 ms 的进程 CPU 时间，仅用于辅助归一化，不是主线程关键路径耗时。

本次可确认 GPU 收益；不能声称同帧率下同时省 CPU。CPU 上升的具体来源需要单独分析，不能再全部归因于提交帧数。只有一轮两版配对，桌面并未隔离其他任务，不能把幅度当成跨机器、跨场景固定开销。

CPU 采样各完整 60 秒。GPU 滚动计数器覆盖：基线 60.000129750 秒、优化版 59.999410875 秒。FPS 来自原生 layer 呈现计数器，约 60.02 / 60.00。GPU 时间是计数器的帧加权平均，区间可能交叠，不能直接取倒数推导帧率上限；窗口 GPU 比例不是整机占用，footprint 是统一内存进程占用，不是独占显存。
