## 根因、共享位置与边界

根因属于公共组件契约：版本、冻结提交与确认策略原先只在 Gallery 的表单文件适配器里。`controls/src/draft.rs` 提供值拥有的 DraftJournal、DraftRevision、DraftSubmission；复用原 TextInput 和既有原子文件适配器，没有新增 UI 组件、token、运行时 JSON、文件发现或网络层。

消费方提供稳定作用域身份、请求身份、存储编码与保存回调。共享协议生成版本绑定的幂等键；保存成功后才交出提交值。失败不替换 journal，编辑器仍可保留未保存输入；重试保持原快照、版本、请求和幂等键。确认必须匹配作用域、版本和请求，不清空当前内容。串行 pending 先重试或确认，新输入可继续生成新版本。恢复拒绝跨作用域、未来版本、重复请求及同版本不同内容，既有数据不静默修复。

适用范围是需要显式草稿/提交协议的消费者，普通输入框不自动启用。存储原子性、跨进程并发、服务端幂等执行与业务撤销仍由消费方负责，不把本地夹具说成生产端到端送达。恢复接受既有队列中尚未发送的 attempts=0 项，但禁止确认这些项，首次发送仍须先保存。

## 真实接入与合理例外

Gallery DurableDraft 复用原绝对路径和原子临时文件→同步→重命名→目录同步路径，保留 v1 文件格式，增添身份和请求元数据；旧文件只读导入，不在打开时改写。默认表单使用同一公开 journal 的内存模式，界面明确区分内存与磁盘。请求文件配置失败时不能降级成内存提交。marked text 活跃时阻止冻结旧的已提交文本；IME 本体沿用原路径。

独立 composition-consumer 接入真实 Rich Dialog/TextFieldContent，另有消费方自己实现的原子文件适配器；不是复制 Gallery 的状态机。失败后保留实际编辑器、重启恢复、错作用域拒绝、重试原快照与迟到/重复确认分别断言。
