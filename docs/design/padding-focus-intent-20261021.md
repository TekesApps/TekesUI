# Issue 34 — read the original padding focus intent

`ContentHost::padding_focus_target(&ContentEvent) -> Option<ComponentId>` lets a host apply its own IME barrier before forwarding a native event. It uses the original registered padding classification, including original mount identity, active/enabled ancestry, registered text target availability, semantic clip and real interactive bounds. No Agent model or input state is added to the SDK.

For a composing editor, the host may allow a primary down when the query returns that same original editor. Keep the existing policy for direct editor input and explicit nonfocusing business navigation. A `None` is not permission to forward: it may identify a real child action, overlay, capture, other phase/button, missing declaration, invalid subtree, stale ownership or an unavailable target. Do not allow the entire input band or copy the private hit rules.

The query takes `&self` and delivers nothing. Focus, reveal, caret, marked text, selection, undo, action queue, capture and native key/IME epochs remain unchanged. Use the result only in the same UI turn; it is not an authorization, reservation or mount token. Forward the original event to `event` / `event_with_text`, which checks the current route again. Pending stale ownership is conservatively rejected until normal reconciliation; the query never reconciles by cancelling input.

Shared implementation is in `composition.rs`, on the original ContentHost and Content::padding_focus_at. Dispatch uses the public query after its normal capture/overlay processing. An open overlay which declines a pointer down no longer leaks that down into decorative padding. Ordinary controls retain their existing action/hit/AX and style contracts. A modal still permits registered padding inside its own current scope; background padding remains excluded.

Applicable consumers are passive input surfaces around original TextSurface owners and real sibling actions, including the existing TextField/TextArea/SearchField adapters. `set_padding_focus` remains editable-only; `set_padding_text_focus` explicitly admits an original selectable read-only owner. The query applies the registered policy and returns the same read-only owner without changing its read-only state. Read-only padding is focus-only; direct text selection retains its original pointer mapping. A host composing in another editor must retain its cross-owner barrier before forwarding this known padding intent. The consumer helper `padding_ime_admission` returns a decision only for recognized padding; `None` keeps the host's existing direct/overlay policy. Remount/replacement requires explicit rebinding. No new token, state abstraction, editor wrapper or capture engine is introduced.

Verification is layered in `design/reviews/padding-focus-intent-20261021`: missing-API failure, a reproduced unconsumed-overlay focus leak, public-API consumer regressions and real GPU input-band rendering. The native host observes the query before forwarding original pointer events and checks unchanged focus/edit baselines. Synthetic preedit is labelled separately from physical IME. AgentKit must independently verify its actual Composer barrier on a new immutable increment; prior fixed candidates remain unchanged. VoiceOver hearing and whole matched ClientKit/Gold7 page acceptance are not inferred from these scoped checks. Performance is not measured.
