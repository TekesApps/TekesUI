# 街区生活效果与原生性能复测（2026-10-21）

当前 worktree 的 release 原生 App，包含窗内人物/动作、入住率、窗帘、夜间随机灯光、路灯地面光照、车灯、施工停工，以及本次新增的防尘幕布和施工品牌横幅。没有提交，也没有清理其他已有改动。

## 条件与结果

Apple M4，10 逻辑核，32 GiB 统一内存，macOS 26.6.2。窗口内容 1512×833 pt、2× backing，3D 渲染目标 2960×1362 px、4× MSAA。夜间模式从相同初始时间开始；持续旋转组同时保留街区动画。Animation 菜单保持打开，以验证原生 common-runloop 下可见窗口持续渲染。其他桌面程序未关闭，结果仅归属目标 PID，不代表整机空载测试。

每组 CPU、轻量 GPU Overview、资源分配各独立记录 60 秒（资源跟踪中旋转组为白天，另列条件），避免把高开销资源跟踪混入性能数字。CPU 数据来自进程累计 user+system 时间的每秒差分；100% 表示占满一个逻辑核。CPU P95 为每秒采样的分位数。

| 指标 | 街区动画 | 动画＋持续旋转 |
|---|---:|---:|
| CPU 平均 | 7.27% | 8.36% |
| CPU P95 | 8.57% | 9.15% |
| CPU 单秒最高 | 9.51% | 9.55% |
| 原生呈现 FPS | 58.12 | 59.78 |
| GPU 每帧活跃时间，按帧数加权 | 16.75 ms | 16.35 ms |
| 窗口级 GPU Usage，按时间加权 | 97.07% | 97.61% |
| 进程 physical footprint 范围 | 492.22–493.13 MiB | 498.70–499.42 MiB |

夜景动画 GPU 补测时，另一个资源记录仍在进行 CPU 索引/保存；桌面后台负载未隔离，因此这些是当前桌面环境的结果，而非专用空载机器的上限。

GPU 使用 Metal Performance Overview 的目标 PID / 原生 layer 指标。GPU Usage 为该窗口 GPU 活跃时间与帧间隔的比值，**不是整机 GPU 利用率**。夜景两组均接近 60 FPS，GPU 已接近满帧预算。两次请求录制均为 60 秒，滚动计数器覆盖分别为 60.0790 / 60.0002 秒。GPU 窗口均值不等于单帧 P95。

当前 CPU 没有出现高占用；夜景两组 GPU 使用约 97% 的帧预算，固定视角约 58 FPS，持续旋转约 60 FPS。下一步应优先定位局部灯光、阴影和像素着色开销，不能声称 GPU 还有充足余量。这次没有更改通用渲染器性能策略，不能把本次数据当作同条件优化前后的收益。

## 统一内存与 Metal 分配

M4 的 Metal 资源与进程共享统一内存，不能把 Metal 分配和 physical footprint 相加。资源跟踪单独进行，不采用其 CPU / FPS / GPU 时间作为性能结论。

街区动画的 60.0458 秒 Metal 分配计数器：稳定中位数及末值均为 **258.67 MiB**，按时间加权均值 **261.66 MiB**。计数器还报告过 **1746.63 MiB** 的短暂最大值；超过 400 MiB 的累计时间只有 **0.122 秒**。

交叉检查同一记录的 10978 条目标进程 Allocation / Deallocation 事件，最大单笔分配为 128 KiB，全部事件累计净增长峰值只有 1.50 MiB，无法解释该 1.7 GiB 峰值。未跟踪的 CPU 测量中进程 footprint 也保持稳定。因此这是尚未解释的资源计数器异常，不能宣称已证明为实际常驻显存增长，也不能把峰值静默删除。后续如排查内存泄漏，应同时比对分配事件、Metal 计数器和未插桩的进程内存。

旋转资源组（白天，60.0542 秒）共 41514 个样本，Metal 分配始终为 **258.67 MiB**，没有出现上述异常峰值。这项补测验证旋转时的资源稳定性，但不能替代夜间旋转的显存峰值测量；夜间旋转的无插桩 physical footprint 范围见表。

## 防尘幕布与广告

新增独立资产模块 `city_construction.py` 和 glTF 节点 `construction-dust-screen`。四面织网位于脚手架外侧，随楼层搭高，竣工后与脚手架按层拆除，夜间施工时钟冻结。横幅采用原创虚构 TEKES BUILD 标志及 BUILDING TOMORROW 广告，包含低层和高层布置，避免引入第三方品牌资产。

新增 112 个索引顶点、56 个三角形，一张 128×128 MASK 织网纹理、一张 384×64 横幅纹理。沿用已有 wgpu GPU 分层动画，不逐帧生成或上传幕布/广告几何。

## 验证与记录

- 14 个 viewer 测试通过，包含 GPU 动态独立性、像素可见变化及不重复上传几何。
- 10 个 scene3d 普通测试通过；该命令中另外 8 个独立 GPU 测试标记 ignored，不能据此宣称该组全量通过。
- tekes-ui-3d 全 targets Clippy `-D warnings` 通过。
- Metal Overview 汇总回归测试 3 项通过：帧数/时间权重、进程隔离、中心窗口裁剪、拒绝不足时长及无持续呈现的样本。
- 高开销 GPU+Resource Events 详细跟踪有一次保存时崩溃，已排除；最终 GPU 表使用两组成功完成的轻量 Overview 记录。
- 截图复核发现早先轻量 GPU 补测已处于白天，因此那两组数据不能代表夜景；最终表只采用重新明确选择 Night 后的记录。
- 原生 App / 资源 SHA256、逐秒 CPU 数据、GPU 汇总及分配事件交叉核对见同名 JSON。原始仪器文档可能包含进程环境信息，不纳入仓库。
