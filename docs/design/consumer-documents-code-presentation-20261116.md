# Consumer documentation and shared code presentation

Baseline: v0.3.32, source 882a60a / merged 601dc83. User request 2026-11-16.

Gallery Documents continues to bundle Markdown sources through the existing document registry and to compose ScrollContent with RichContent. It remains a selectable read-only reader, not a new editor, browser, or Markdown projection-editing system. Future projection editing in #132 is unchanged.

Use the existing bounded Markdown blocks (headings, paragraphs, bullets, links, fenced code) for all consumer manuals. Do not claim full CommonMark, tables, inline styled-font shaping, arbitrary HTML, or remote content. Do not fake bold/italic/code-font layout by painting over differently shaped text. Unsupported syntax must be documented honestly; manuals should use supported forms so readers do not see formatting delimiters.

Add source-code coloring in the shared rich-document path, using the existing fenced language metadata and shared c-code-keyword, c-code-string, c-code-number, c-code-comment colors. No Gallery-specific parsing or colors, no second Theme engine. Retain original paragraph shaping, Unicode cluster positions, selection, copy, source mapping, clipping and scroll ownership. Use a maintained syntax parser (evaluate syntect 5.3.0 parsing/default syntaxes with pure Rust regex, no themes/HTML machinery) rather than an ad-hoc language lexer. Unknown/omitted languages are explicitly plain text. Parser errors must be exposed through the existing fallible Content construction/update path, not concealed as successful highlighting. Only static syntax data may be shared; do not build a new cache framework.

All 45 registered component manuals plus the supplemental manual become English, consumer-oriented guidance: purpose/when to use, minimal public API example, key properties and state, events, composition/scroll/focus responsibility, supported limitations, related APIs. Preserve already typechecked code snippets unless a changed contract requires updating them. Remove internal Check numbers, local receipt paths, status matrices and delivery bookkeeping from reader-facing text; preserve those in design/Issue history. Follow Apple AppKit documentation's overview and topic-oriented organization, without copying their prose or pretending TekesUI APIs match AppKit.

Acceptance: actual keyword/string/number/comment token color selection in light/dark; unchanged selection/copy/source mapping and geometry; explicit plain unknown language; public consumer with existing RichContent; English registered manuals without leaked internal verification logs; narrow native Documents observation. Input/Clear/I-beam work is a separate Issue; no shared-file concurrent writers. Root owns Gallery integration, dependency locks, generated metadata, shared builds, CI/public delivery and Dock. Reuse unaffected evidence.

References: https://developer.apple.com/documentation/appkit/nstextfield ; https://developer.apple.com/documentation/appkit/nssearchfield ; https://docs.rs/syntect/5.3.0/syntect/parsing/struct.ParseState.html .

Implementation candidate: RichContent owns private rich_content/syntax.rs parsing and retained UTF-16 color spans. RichDocument projection and mapping remain unchanged. Parsing completes before new/update mutates editor state; errors return RichContentError::Syntax(String). The renderer partitions retained glyphs by their original cluster-start color, leaving layout, source maps, selection and copy intact. Shared SyntaxSet initialization is the only shared syntax state.

Verification prepared: two parser regressions cover Unicode offsets, multiline comment state, unknown/omitted languages and reset between fences. The public consumer checks all four palette tokens in light/dark, equal original Paragraph geometry, equal painted glyph count and unchanged Unicode copy. The 46-manual audit confirms English prose, supported prose forms, no internal receipt leakage and byte-identical original Rust fences. Compilation/runtime outcomes are recorded separately after the coordinated window; static audit is not native acceptance.
