# Issue 30 — retained editor padding focus

Root cause: ContentHost has direct focus and child pointer routing, but passive decoration cannot declare a focus destination. Consumers would otherwise recreate hit/focus timing and risk blur/refocus or numeric-ID reuse.

Shared fix: `ContentHost::set_padding_focus(owner, Some(editor))`, stored on the original Content with its existing mount identity. Classification happens before ordinary primary-down dispatch, after overlay/key/capture handling. Actual interactive bounds shield the decoration regardless of consumption/disabled state. Existing library focus performs an atomic owner change. Same-owner padding is consumed without repeating set_focus/reveal; no pointer coordinates, caret mapping, capture or AX clone is created.

Applicability: passive composed input surfaces with an original editable TextSurface descendant (TextField/TextArea/SearchField adapters or compatible Component). AgentKit Composer is the first receiver; no Agent domain types or presentation state belong here. ClientKit reference checked: original ComposerMarkdownEditor Container.mouseDown guards nativeEnabled and focuses its retained state.handle; its product implementation remains unchanged.

Exceptions: read-only targets retain their direct selection and AX contract; padding does not redirect to them. Actual sibling buttons/links retain ownership, including disabled bounds. Secondary pointers, outside/clipped padding, active capture, inactive/disabled ancestry, foreign/subtree moves and replaced/remounted targets cannot invoke the declaration. Rebinding is explicit after remount/replacement. No token values/styles change; no new component or default migration.
