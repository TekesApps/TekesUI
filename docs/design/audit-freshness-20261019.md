# 组合审计的提交与导出可复验性（#6/#8/#14）

当前组合矩阵已精确绑定被审计源文件 SHA-256、全部 45 个组件和 API 路径/行/声明锚点，但检查器同时要求运行时 Git HEAD 必须等于记录的审计基线。这会让相同字节在提交后的 CI 或独立导出中失效：试图把新 HEAD 写入同一次提交也无法得到固定点。

修复复用 capability 清单既有内容寻址规则。矩阵保留原始 40 位不可变 Git 基线作为来源；当前有效性由真实源字节及公开绑定锚点验证。提交或导出相同内容不会自动变成陈旧，任何受审计源文件变化仍必须显式复核并重绑，不能自动刷新结论或提升体验状态。

先红后绿的回归使用不含 .git 的真实审计源导出验证：相同源文件通过，修改实际源而保持矩阵 hash 不变会拒绝；将基线改为 main 也会拒绝。原有漏组件/重复组件、错 hash、伪行号、漏注册 API、叶子强制 children、将静态审计升级为原生接受的负例全部继续通过，共 8 项。

这是检查器与可交付审计的缺陷修复，没有改运行时或公共组件，也不代表 #14 全组件迁移完成。当前全部组件继续 experimental。完整记录见 design/reviews/issues1-14-closeout-20261019/audit-commit-red.log、audit-commit-green.log 与 python-final-gates.json。
