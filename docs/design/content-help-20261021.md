# Issue 35 — help on the original Content owner

`Content::with_help(text)`, `set_help(Option<String>)` and `help_text()` declare/update/revoke dynamic explanation on the retained original owner. `ContentHost::help_tooltip()` returns only a currently valid painted owner/text/layout. No extra row, editable surface, primary action, focus target or AX node is created. Equal text is a no-op; whitespace-only clears. Text updates preserve existing click/Escape/geometry dismissal until a fresh original hover/focus request; metadata never substitutes for input. Removal clears the declaration, so retained/remounted objects explicitly rebind; reordering retains ownership.

The current semantic projection appends help to an intrinsic component description without discarding validation/state information. The existing macOS mapper already publishes that description as `accessibilityHelp`. Button name/value/action identity and original parts remain authoritative. The actual Sidebar consumer retains query-isolated typed snippets and supplies only current text, as ClientKit rowHelp does; the SDK has no Agent/search domain state.

Routing uses the current original mounted/visible owner, clipping, action-child shielding, modal scope and capture/overlay priority. Hover and explicit keyboard/AX focus use the existing host clock and request_animation_frame with a JSON-bound500ms dwell, independent of Reduced Motion. A popup neither focuses nor reveals, captures, activates, edits preedit/selection/undo, advances an editing epoch nor changes a reading offset. Pointer exit, click/action, scrolling, Cancel/window loss, moved/clipped owner, text change/revocation, lost clock and unmount invalidate old presentation. Escape dismisses passive help without stealing a composing editor's key. Original native adapters must continue delivering Cancel on window loss and reject inactive input, as in existing hosts.

The original TooltipView owns palette, chrome, placement and suppression; a small private ContentHost state tracks only declaration identity, route and dwell. Existing Tooltip/TooltipView callers remain supported. Help is a noninteractive attachment, not arbitrary content slots or a standalone TooltipContent. Disabled controls may retain explanatory help while their original actions reject activation.

Sizing reuses the original Tooltip insets and viewport placement, UiCaption and the original font renderer. Readonly label layout uses actual shaped row ends and existing tail ellipsis, including fallback-font/type-scale metrics; a nominal M height is insufficient. An editing TextSurfaceHost does not imply shape_label support. When readonly shaping is unavailable, reuse the caller's original text renderer for text that fits; otherwise retain full semantic help and suppress a blank/clipped popup. Missing host clock similarly leaves semantic help only and requires fresh owner input after restoration. No new font backend or editor instance is introduced.

Shared locations: composition.rs plus private composition/help.rs; original TooltipView fitted-size helpers; existing readonly LabelRenderer failure observation; generated optional tooltip_hover_delay binding in design-export/effects.rs. `design/source/interaction-contracts.json` is the sole new timing definition. Existing color/size/spacing/type token values and default undeclared behavior stay unchanged. The new methods/private metadata and optional generated binding are additive; old artifacts without the help timing return None, not an invented fallback value.

Verification lives in `design/reviews/content-help-20261021`. Missing public API, pending AX-Press rearm, missing readonly label service, lost-clock stale visibility and actual clipped glyph bounds have separate failed/repair logs. The early GPU green result was rejected after inspecting empty help and then clipped first lines; those captures remain historical. Final public API, original consumer, GPU/token, active external native and actual AgentKit Sidebar acceptance are separate, source-bound layers. Synthetic preedit does not establish physical IME; mechanical Gold7 gates are not a matched whole product-page visual signoff. No performance measurement or Git publication/closure.


## Deferred window overlay intake — 2026-10-27

`ContentHost::set_help_overlay_deferred(true)` lets the original host render its content first; the caller then uses `paint_help_overlay(scene, text, window_viewport, palette)` once after other content. This reuses the same help owner, dwell clock, TooltipView and suppression. It does not replay buttons, allocate another input owner or change normal undeclared rendering. The separate pass requires an active window, current layout and no reading transaction; retained old geometry cannot authorize a late paint.
