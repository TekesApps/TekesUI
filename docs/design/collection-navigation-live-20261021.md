# DataTable：模型变化期间的键盘焦点

根因属于公共组件契约。DataTableView 的指针入口已经检查最新模型，键盘导航却仍可能采用旧布局内已删除的行，或直接按新列数移动到尚未挂载的表头。两种情况都会把焦点留在下次 Enter 无法使用的目标。两个公共 API 回归在修复前真实失败。

共享修复只在 `collections_view.rs::DataTableView::key`：行候选按当前 `model.rows` 过滤；表头候选取已挂载表头与当前列数的交集，复用现有 `row_key_target`。没有新 token、状态层、协议或公共签名；没有改变布局、文字、命中区域及调用方模型。适用于所有 DataTableView 消费者，包括排序后的源行顺序及重排绘制前的模型变化。

合理例外：ListView 已有最新行数过滤，TreeView 已读取当前可见且启用的节点，本轮不重复迁移。新增列在实际布局发布后正常参与导航。不承诺从未观察到的模型 ABA 变化或稳定业务身份；这些仍由现有调用方模型／组合身份契约负责。

- 真实接入：168 消费者测试、13 项当前 Gallery 集合回归通过。独立小宿主抽取当前 Gallery 原样 focus_changed，使用真实 DataTableView、CoreText 和 Metal，没有复制状态机。
