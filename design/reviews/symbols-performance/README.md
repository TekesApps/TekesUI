# 图标动画 120Hz 与 CPU 实测

**结论：当前实现未达到稳定120Hz零掉帧。** 24实例三种常用负载在各60秒中均出现实际呈现长间隔；72实例压力组已出现明显CPU预算超时。停止后的空闲回归通过。

## 环境与口径

- Apple M4 / Mac16,1，macOS 26.6.2 / 25G83，低功耗模式关闭，内建Retina / ProMotion120Hz，2×，Fifo / 三drawable。
- 正式组关闭GPU时间戳查询，与普通预览的查询设置一致；公开Metal presented回调为测量开启。GPU时间戳只在单独诊断组启用。
- 每组先预热1.5秒，表中秒数仅测量期。之后暂停全部控制器，等待5秒检查空闲。启动的一次性SVG解析、字体预热不在持续播放CPU数据中。
- CPU100%是一个逻辑核心的user+system，峰值为250ms采样；不是整机核心总和。
- 长间隔指相邻实际presentedTime超过1.5×刷新间隔，即12.5ms；它是一次事件，可跨过多次刷新。显示链接漏刷新另列，不能拿p99/平均帧率代替完整记录。

正式组的呈现收据均完整：missing receipts=0、not presented=0；模型错误=0。所有模型结束后都暂停成功，5秒内额外显示链接回调=0，空闲进程CPU约0.037%～0.087%。这表示停止/空闲回归通过，不表示持续播放零掉帧通过。

42实例组在20秒内未见实际呈现长间隔，但仍有1次回调漏刷新，CPU帧峰值超过8.33ms。不能由这一短测或p99推导全部效果、所有负载的严格通过。

## 负载定义与限制

- 一个source对应Whole / ByLayer / Individually三个同时播放实例。3实例基线是设置图标呼吸；24实例是8个独立控制器；72实例是24个独立控制器。它们复用8个批准图标，不是72种不同图标。
- 24/72组混合呼吸、弹跳、脉冲、摇摆、旋转、路径描绘、关联替换和变量颜色；42组覆盖全部14效果。基线与混合组内容不同，不能据此推导纯数量的线性伸缩。
- 调参使用实际MotionPreview::set_parameter，每个显示回调修改至多3个适用参数，并每1.2秒缓慢反向保持运动；切目标使用实际MotionPreview::retarget，每180ms反向。压力组同时做两者。
- 这些是自动化接口输入，不是物理鼠标、触控板或输入到显示延迟测量。基准走真实SVG路径、光栅化、纹理更新、场景/渲染和原生窗口呈现；不以只跑数学的headless结果替代。
- 固定纹理组仍推进控制器、绘制同样24个图像实例，但不再逐帧重画/上传。它是故意去掉动画像素更新的诊断对照，绝不算动画通过证据。
- GPU诊断只覆盖本进程render pass，不含合成器和drawable等待；其结果不能直接代替正式组GPU时间。正式组gpu_ms=null，表示未测而不是0。
- 这次使用同一份冻结、签名的二进制顺序运行。中途为用户更高优先级滚动校准暂停调度，当前组和5s idle完成后才让出资源；无未完成组被拼接进结果。恢复后未重新编译。主会话之后的scroll修复不自动继承这份整机测试。
- 运行于用户共享桌面；每组开始前保留本地进程清单，未并行运行本项目构建/其它GPU基准，仍不能排除系统/用户活动对零星峰值的影响。

## 已定位与尚未归属

1. 控制/模型本身很轻：24实例稳态平均约0.007ms，连续调参约0.073ms，切目标约0.034ms。持续SVG重画、全量纹理上传及少量场景工作占据主要建场景时间，24实例平均约3.1～3.3ms；72实例压力平均准备约7.09ms、建场景p99约10.80ms。
2. 固定纹理诊断的CPU均值为16.85%，相较24实例混合动画46.24%显著降低；建场景平均3.21→0.047ms。此为不同顺序/时段运行的诊断，不是严格随机化A/B；但结合分阶段计时，支持优先优化SVG光栅化和上传路径。
3. 固定纹理仍有2次实际长间隔；24实例稳态捕获到最长13.39ms的drawable等待。故不能把所有掉帧归因于模型或CPU。呈现、合成器/背压归属需要独立继续查。
4. GPU时间戳诊断均值约0.418ms、p99约1.537ms，但峰值10.899ms；不能只报均值来否认GPU异常，且这个诊断不是每个正式组的GPU证据。

## 后续优化方向（本轮未实现）

纯位移/缩放/透明度效果优先复用已缓存图层并在GPU变换，减少逐帧SVG重画与全量上传；路径描绘与替换再针对性缓存/渲染。同时独立分析drawable等待和实际呈现异常。优化后必须重跑同样矩阵，不能放宽阈值或改成只看p99。

## 复现和原始证据

- build-measured.json：冻结签名二进制SHA256、源码清单和WIP声明；build-before.json保留早期smoke候选。
- summary.json：全部正式、诊断与smoke的聚合，保留失败数据。raw/*.json.gz：原始完整每帧JSON（无丢弃或重采样），raw/manifest.json给出原文与压缩文件哈希。
- 完整未压缩JSON、日志、启动进程记录：工作目录target/symbol-perf/。进程清单仅保留本地，未纳入归档。
- scripts/measure-symbols.py：单组；scripts/measure-symbols-matrix.py：顺序矩阵；scripts/summarize-symbol-perf.py：汇总。矩阵拒绝覆盖同名已有记录，重跑可用`--prefix repeat-`或`--out target/symbol-perf-repeat`。
- 运行示例：`python3 scripts/measure-symbols.py --binary "target/TekesUI Symbols Benchmark.app/Contents/MacOS/TekesUI-Symbols-Benchmark" --sources 8 --mode parameters --seconds 60 --gpu-timing 0 --label repeat-parameters-24`。

测量进程退出0只表示完整运行并回归空闲，绝不等于零掉帧通过。本轮新增harness、自动化脚本及数据；未修改生产动画实现来“优化”结果。

验证：8项perf相关单测、Gallery all-targets严格Clippy、pure Rust边界（542文件）和scoped diff检查通过。源文件后续变动单独记录在source-drift-after.json，不会回填修改测量来源哈希。
