## 落实到 v0.3 的决定

以下是 **Tekes 的设计取舍**，不是声称 Jenny 发布了这些 token、数值、schema 或验收清单。

| 参考观点 | v0.3 的具体契约 |
|---|---|
| 真实体验比流程完整重要 | Gallery 必须使用真实组件；静态报告不等于原生实现或页面通过。新增 `craft-review.json`，逐项记录实际证据。 |
| 探索不必严格线性 | 可先试布局、视觉或可操作原型；冻结发布仍走唯一真源、版本、哈希与 16 类门禁。 |
| AI 内容不确定 | UI 状态与事件保持确定；增加延迟、中断、畸形富文本、拒绝审批等内容场景，而不是声称穷举模型回答。 |
| 有选择地披露复杂度 | 调用细节可展开；权限、计划批准、取消、错误和证据不能因为“简洁”而消失。 |
| 判断力与执行质量重要 | Agent 交接必须保留 token 别名、组件 ID/API、行为边界和未验证项；不只给截图。 |
| 愉悦感是产品体验的一部分 | 优先清楚的文案、及时且有意义的反馈；保留无阴影、中性焦点与减少动态规则，不增加持续装饰。 |

[NN/g 的回应文章](https://www.nngroup.com/articles/design-process-isnt-dead/)提供重要制衡：流程压缩不等于不需要理解问题和验证。[REVIEW-01] 本项目因此区分 **灵活探索** 与 **严格发布**，不删既有验收要求。
